Section I: Bezier Curves and Surfaces

Part 1: Bezier curves with 1D de Casteljau subdivision

De Casteljau's algorithm is a recursive algorithm used to evaluate points on a Bezier curve. Given \(n+1\) control points \(P_0^{(0)}, P_1^{(0)}, \ldots, P_n^{(0)}\), the algorithm evaluates the Bezier curve at parameter \(t \in [0,1]\) by recursively computing

\[ P_k^{(i+1)} = (1-t)\, P_k^{(i)} + t\, P_{k+1}^{(i)} \]

After \(n\) iterations, the algorithm produces a single point \(P_0^{(n)}\), which is the point on the Bezier curve at parameter \(t\).

This is implemented in evaluateStep. Given the \(n+1\) control points points, we first allocate an array result of size \(n\), then define

\[ \texttt{result[i]} = (1 - t) \cdot \texttt{points[i]} + t \cdot \texttt{points[i + 1]} \]

BezierCurve::drawCurve then calls the function until only one point remains.

Part 2: Bezier surfaces with separable 1D de Casteljau

For Bezier surfaces, we are given \((n+1)^2\) control points \(P_{i,j}\), where \(i,j = 0, \ldots, n\). To evaluate a point at \((u,v) \in [0,1]^2\), we first perform the 1D de Casteljau algorithm in the \(u\)-direction, namely on each sequence of control points

\[ P_{0,j}, P_{1,j}, \ldots, P_{n,j}, \qquad j = 0, \ldots, n. \]

This produces \(n+1\) intermediate points \(Q_0(v), \ldots, Q_n(v)\), where each \(Q_j\) is obtained by evaluating the corresponding Bezier curve at parameter \(u\). We then apply the 1D de Casteljau algorithm to these \(n+1\) intermediate points in the \(v\)-direction, producing the final point on the Bezier surface at \((u,v)\).

This is implemented using three functions:

  • BezierPatch::evaluateStep: Given a sequence of control points, return the control points at the next level. This is implemented in the same way as in Part 1.
  • BezierPatch::evaluate1D: Given a sequence of control points and a parameter \(t\), return the corresponding point on the Bezier curve. This is implemented by repeatedly calling evaluateStep until only one point remains.
  • BezierPatch::evaluate: Evaluate the Bezier patch at parameter \((u,v)\). We first call evaluate1D on each sequence of control points in the \(u\)-direction and store the resulting \(n+1\) intermediate points in an array. We then call evaluate1D on these intermediate points with parameter \(v\) to obtain the final point on the Bezier surface.

Section II: Triangle Meshes and Half-Edge Data Structure

Part 3: Area-weighted vertex normals

We first implement a helper function getArea, which takes in three vertices \(a\), \(b\), and \(c\) and computes the area of the triangle formed by these vertices. This can be computed with the cross product

\[ \triangle = \frac{1}{2}\|(b-a)\times (c-a)\|_2 \]

To compute the area-weighted normal, we initialize a zero normal vector av_normal, then:

  1. If the face spanned by the current halfedge h is not a boundary face, compute the area w of the triangle.
  2. Let n be the unit normal of the face. Update the accumulated normal as av_normal += w * n.
  3. Update the halfedge with h = h->twin()->next(). This brings us to the next triangle.

We repeat these steps until we return to the starting halfedge. Finally, we normalize av_normal to obtain the area-weighted vertex normal.

Part 4: Edge flip

To implement the flip operation (ignoring boundary edges), we first label all geometric objects, including all halfedges, vertices, and faces. The steps are:

  1. Rewrite the halfedges. We rewire the halfedges using setNeighbors. For example, for the halfedge h_bc, its next should be h_dc, and it should now start at vertex a. We thus call \[ \texttt{h_bc->setNeighbors(h_dc, h_cb, a, e0, f_left)} \]
  2. Rewrite the vertices. After the halfedges have been rewired, we update the halfedges stored by the affected vertices. For example, we set the halfedge stored by b to h_bd, since h_bc now starts at a. Similarly, we set the halfedge stored by c to h_ca.
  3. Rewrite the faces. Finally, we set the halfedges stored by the left and right faces to h_bc and h_cb, respectively.

Part 5: Edge split

To implement the split operation, as in the previous part, we first label all geometric objects, including all halfedges, vertices, and faces. The steps are:

  1. Create new geometric objects. We create a new vertex m at the midpoint of vertices b and c. We also create two new faces, three new edges, and six new halfedges. The original edge e0 is reused for the edge connecting b and m.
  2. Rewrite the halfedges. We rewire the halfedges using setNeighbors to form four triangles. For example, for the halfedge h_bc, its next should be h_ma, and it should still start at vertex b. We thus call \[ \texttt{h_bc->setNeighbors(h_ma, h_cb, b, e0, f_left)} \]
  3. Rewrite the edges. We set the halfedges stored by the new edges e_mc, e_am, and e_dm to h_mc, h_am, and h_dm, respectively. We mark e_am and e_dm as new edges, while marking e0 and e_mc as segments of the original edge.
  4. Rewrite the vertices. We update the halfedge stored by each vertex to an outgoing halfedge. For example, we set the halfedge stored by m to h_cb, which now starts at m and points to b. We also mark m as a new vertex.
  5. Rewrite the faces. Finally, we set the halfedges stored by f_left, f_right, f_left_new, and f_right_new to h_bc, h_cb, h_mc, and h_cm, respectively.

Extra Credit: Boundary Edges

The interior implementation does not support splitting boundary edges. Unlike an interior edge, a boundary edge is adjacent to only one non-boundary triangle, so we split this triangle into two rather than four. The implementation is similar, with the following differences:

  1. Create new geometric objects. We create one new vertex m, one new face, two new edges, and four new halfedges.
  2. Rewire the halfedges. We update the halfedges to form two interior triangles, while also updating the virtual boundary loop from c -> b to c -> m -> b.
  3. Rewrite the remaining objects. As before, we update the representative halfedges of all affected edges, vertices, and faces, and mark the newly created connecting edge e_am as new.

Part 6: Loop subdivision for mesh upsampling

To implement Loop subdivision, we follow these steps:

  1. Compute new positions for all vertices. For each vertex \(v\), we first compute its weight \(u\). We then traverse its neighboring vertices and sum their positions, and define its new position as \[ (1 - \deg(v)\, u)\, \texttt{v_pos} + u \sum_{v' \in N(v)} \texttt{v'_pos} \] where \(N(v)\) is the set of neighboring vertices of \(v\). We store this result in v->newPosition.
  2. Compute new vertex positions for the edges. For each edge \(e\), we identify the positions \(A\) and \(B\) of its endpoints and the positions \(C\) and \(D\) of the opposite vertices in its two adjacent triangles. The position of the new vertex that will be inserted when splitting the edge is given by \[ \frac{3}{8}(A+B) + \frac{1}{8}(C+D). \] We store this result in e->newPosition for use after splitting the edge.
  3. Split the original edges. We first store all original edges in a list and mark them as original edges. We then iterate over this list and split each non-boundary edge, ensuring that newly created edges are not split again. For each inserted vertex m, we set m->newPosition to the position previously stored in e->newPosition. The splitEdge function marks the inserted vertex and new edges appropriately.
  4. Flip the new edges. We iterate over all edges and flip each new edge that connects an original vertex to a new vertex. We identify these edges by checking that e->isNew is true and that the isNew flags of its two endpoints differ.
  5. Update the vertex positions. Finally, we copy v->newPosition into v->position for every vertex to apply the positions computed earlier.

The images below show Loop subdivision applied to cube.dae. As we perform more subdivision iterations, sharp corners and edges become more rounded, and the surface becomes smoother. This is because every new position is a weighted average of the old vertex and its neighbors.

We can reduce this rounding by pre-splitting selected edges. Intuitively, pre-splitting adds vertices closer to the sharp corners, which can reduce how far these corners move during the averaging step. This can be seen by pre-splitting each of the 12 edges of the cube before applying Loop subdivision. With pre-splitting, we observe a more corner-like shape.

From the figure above, we also observe that after several iterations of Loop subdivision, the cube becomes slightly asymmetric. This is because its initial triangulation is asymmetric. Each square face contains only one diagonal, giving the corners different neighbor configurations.

To address this, we split the diagonal of each square face (adding a vertex at its center and dividing it into four triangles). This gives a symmetric triangulation. As seen below, this makes the resulting Loop subdivision symmetric.

Extra Credit: Meshes with Boundary

In the implementation above, we skip splitting boundary edges. This results in jagged boundaries after Loop subdivision (Figure a). However, even if we enable splitting for boundary edges, the boundaries remain jagged (Figure b).

Intuitively, this zigzag behavior arises from how vertex positions are updated. Recall that the new position of an existing vertex is defined as

\[ (1 - \deg(v)\, u)\, \texttt{v_pos} + u \sum_{v' \in N(v)} \texttt{v'_pos} \]

For boundary vertices, this rule averages over both boundary and interior neighbors, which pulls the vertices inward. Meanwhile, newly inserted vertices are placed at the midpoints of the original boundary edges. This causes alternating inward and outward displacements along the boundary, producing a zigzag pattern as we see in Figure b.

To fix this, we update each boundary vertex using only its two neighbors along the boundary, ignoring interior vertices. The new position is given by

\[ \frac{3}{4}\, \texttt{v_pos} + \frac{1}{8}\left(\texttt{v_prev_pos} + \texttt{v_next_pos}\right), \]

where v_prev and v_next are the two neighboring vertices along the boundary. Similarly, for boundary edges, we replace the standard Loop subdivision weighting rule with the midpoint rule

\[ \frac{1}{2}(A+B). \]

After implementing these features, Loop subdivision works correctly on the boundary.

Extra Credit: Modified butterfly subdivision

The Loop subdivision scheme described above updates each vertex position by taking a weighted average of the vertex and its neighbors. As discussed earlier, this can cause sharp corners to become rounded. Modified butterfly subdivision (Zorin, Schröder, and Sweldens, 1996), on the other hand, is an interpolating subdivision scheme that keeps existing vertices fixed and only inserts new vertices. This ensures that the subdivided surface passes through the original vertices, helping preserve the original shape.

On a high level, modified butterfly subdivision first computes the positions of new vertices using different rules depending on the local mesh structure:

  1. Boundary edges: Suppose the boundary contains four consecutive vertices \(A,B,C,D\), and we want to split edge \(BC\). The new vertex is \[ p_{\mathrm{new}}=\frac{9}{16}(B+C)-\frac{1}{16}(A+D) \]
  2. Regular interior edges: If both endpoints have valence 6 (i.e. connected to 6 edges), we use the standard 8-point butterfly stencil, which takes a weighted combination of the edge endpoints and six surrounding vertices, given by \[ p_{\mathrm{new}} = \frac{1}{2}(A+B) + \frac{1}{8}(C+D) - \frac{1}{16}(W_1+W_2+W_3+W_4) \]
  3. One extraordinary endpoint: If one endpoint has valence other than 6, we use a special stencil centered at that endpoint, with weights determined by its valence. For \(K\geq 5\), the weights are some linear combinations of cosines.
  4. Two extraordinary endpoints: If both endpoints have valence other than 6, we compute the new position using each endpoint's extraordinary stencil and average the two results.

After computing the new vertex positions, we split all original edges and flip the appropriate newly created edges, subdividing each original triangle into four smaller triangles. Unlike Loop subdivision, the positions of existing vertices remain unchanged.

In terms of the implementation, we define helper functions to compute vertex valences and the new vertex positions using above mentioned rules. After computing the new vertex positions, similar to loop subdivision, we first store the computed positions in newPosition before modifying the mesh. We then split all original edges, assign the precomputed positions to the inserted vertices, and flip newly created edges connecting an old vertex to a new vertex. Finally, we update the positions of the new vertices while keeping all original vertices fixed.
